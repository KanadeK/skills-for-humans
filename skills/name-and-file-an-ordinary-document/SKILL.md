## 中文

当你手里有一份普通、低敏感的数字文件，却只能靠“下载 (7)”或“最终版_真的最终”猜它是什么时，加载这份 Skill。目标是给它**能说明用途和版本的名字、一个明确的存放位置，并亲自找回一次**。清空整个下载目录、备份、格式转换和发送文件是另外的任务。

只处理你有权改名或移动、且不含需要特殊保护信息的文件。系统文件、软件安装目录、别人管理的共享项目、带有效链接的团队文件、凭据和敏感记录不要直接按此流程批量改动；先找实际负责人确认。

### 准备与输入

打开文件或预览，确认它是什么、用来做什么、当前版本是否仍要编辑。记录原位置与原名，确定一个与你平时找它的方式一致的归档文件夹。先看目标文件夹里是否已有同名文件或更合适的现行版本；不把“同名”当作可以覆盖。

### 执行

1. **给名字留下可检索线索。** 用“主题 + 用途”，需要时加有意义的日期或版本，例如 `2026-09-28_读书会流程_v02.pdf`。日期代表你实际要识别的事件或版本日期；若日期无帮助，省略它。标题里用读得懂的词，不用只有自己今天懂的缩写。
2. **明确版本关系。** 若只有一份正在使用的文件，就不必加 `v1`；若有多个需要保留的版本，把当前版和旧版用同一规则区分。不要靠不断追加“最终”“新版”“最后一次”识别。旧版要不要留，按实际需要决定，别在这一步顺手删除。
3. **保留真实文件类型。** 在文件管理界面重命名名称部分，不随意改 `.pdf`、`.docx` 等扩展名。看不到扩展名时先用系统的显示选项核对；改后确认仍能用原来的应用打开。改扩展名不会把内容转换成另一种格式。
4. **选一个能记住的家。** 按用途或项目选择一个已有文件夹，必要时新建一层有意义的文件夹。避免为一个文件连造多层空目录；文件夹名和文件名一起应让你知道从哪里找。标签或收藏可以帮找，但别让它成为唯一线索。
5. **移动前检查影响。** 如果这份文件被其他文档、应用或共享链接引用，先确认移动是否会让引用失效；不确定就暂停移动并保留原位置。确认目标位置没有同名冲突后，用文件管理界面的移动功能把文件放过去，不选择覆盖已有文件。
6. **按预期线索找回。** 退出“最近使用”视图，从你选的文件夹或系统搜索输入主题/日期/版本，找到并打开目标文件。核对内容与版本，而不仅是文件名。若云同步或外部设备尚未完成，先记录当前实际可访问的位置，不把“正在同步”称为已归档到所有设备。

### 完成条件

你能说出这份文件的用途、现行版本和固定位置，并从该位置或预期关键词把**正确内容**打开一次。若重名、引用关系或权限未查清，保留原件原位并标出待确认事项；不靠覆盖、删除或猜测完成归档。

### 常见报错与补救

- **目标文件夹已有同名文件：** 先打开比较内容与版本；需要两份就给它们不同的可解释名称，不在提示框里随手点“替换”。
- **改名后文件打不开：** 查看扩展名是否误改；按原文件类型恢复名称，仍打不开就停止更多改动并查看软件的恢复方式。改名不能修复或转换文件内容。
- **找到了两个“最新”版本：** 看实际修改内容或有记录的交付版本，选出当前使用的一份，并把其他版本明确标旧或待核对；不要根据文件大小猜。
- **移动后原链接失效：** 不再继续批量移动，向链接的负责人确认修复方式；必要时把单个文件移回记录的原位置并检查引用。
- **搜索不到：** 回到记录的原位置和目标文件夹检查；核对搜索词、版本、同步状态，别因搜索结果空白立刻创建第三个副本。

### 假设、替代与现实副作用

这套命名方法是可调整的例子，不是所有平台强制标准。文件系统、同步服务和团队约定对名称、路径长度与共享引用的处理不同；在实际界面和项目规则内操作。可用屏幕阅读器、键盘操作或系统搜索完成同样的核对；视觉排序不是唯一方式。你可能需要更新自己记住的旧路径，但以后不用在十七个“最终版”里抽奖。

## English

Load this Skill when an ordinary, low-sensitivity digital file can only be identified by a name like “download (7)” or “final_really_final.” Give it a **name that explains its purpose and version, one clear location, and a successful retrieval by you**. Cleaning the whole Downloads folder, backing up, converting formats, and sending the file are separate tasks.

Use this only for a file you are allowed to rename or move and that does not need special protection. Do not batch-edit system files, application directories, someone else's managed shared project, team files with active links, credentials, or sensitive records under this process. Ask the actual owner first.

### Preparation and inputs

Open or preview the file to learn what it is for and whether this version is still being edited. Note its original name and location. Choose an archive folder that matches how you would later look for it. Check whether the destination already has a file with the same name or a better current version. A matching name is not permission to overwrite.

### Execution

1. **Put findable clues in the name.** Use “topic + purpose,” adding a meaningful date or version when useful, such as `2026-09-28_book-club-agenda_v02.pdf`. The date should represent an event or version you actually need to identify; omit it if it adds nothing. Prefer words a future reader can understand over today's private shorthand.
2. **Make version relationships explicit.** One active file need not be called `v1`. If several versions must remain, distinguish the current and earlier ones using one consistent rule. Repeated “final,” “new,” and “last one” labels are poor version control. Decide separately whether old versions should remain; do not delete them as a side effect of this step.
3. **Preserve the real file type.** Rename the name portion in your file manager without casually changing `.pdf`, `.docx`, or another extension. If extensions are hidden, use the system's display option to check. Confirm the file still opens in its original application after renaming. Changing an extension does not convert the content to a new format.
4. **Choose a memorable home.** Use an existing folder by purpose or project; create one meaningful level if needed. Avoid nesting several empty folders for one file. The folder and filename together should tell you where to look. Tags or favorites can help, but should not be the only clue.
5. **Check the effect before moving.** If another document, application, or shared link refers to this file, check whether moving it would break that reference. If uncertain, pause and leave it in place. After checking for a name collision, use your file manager's move action and do not overwrite an existing file.
6. **Retrieve using the expected clue.** Leave the “Recent” view. Search your chosen folder or enter the topic/date/version in system search, then find and open the target. Check its contents and version, not just its name. If cloud sync or an external drive has not finished, record where it is actually accessible; “syncing” is not “archived on every device.”

### Success

You can state the file's purpose, current version, and stable location, then open the **right contents** once from that location or an expected search term. If a name collision, active reference, or permission is unclear, keep the original in place and mark what needs checking. Overwriting, deleting, or guessing is not an archive result.

### Common errors and recovery

- **A file with that name already exists:** Open and compare contents and versions. If both matter, give them different explainable names rather than clicking “replace” in the prompt.
- **The file stops opening after renaming:** Check whether its extension changed. Restore the name for the original file type; if it still fails, stop further edits and check the application's recovery options. A rename cannot repair or convert file contents.
- **Two versions both say “latest”:** Check actual edits or a recorded delivered version; identify one current file and label the others older or pending review. Do not guess from file size.
- **An old link breaks after moving:** Stop further bulk moves and ask whoever owns the link how to repair it. If appropriate, move the one file back to its recorded original location and test the reference.
- **Search returns nothing:** Check the recorded original and destination folders, search terms, version, and sync status. An empty search result is not a reason to make a third copy.

### Assumptions, alternatives, and known side effects

The naming pattern is an adjustable example, not a universal platform rule. File systems, sync services, and teams handle names, path lengths, and shared references differently; follow the actual interface and project convention. A screen reader, keyboard, or system search can verify retrieval; visual sorting is not the only route. You may need to update your memory of the old path, but future you need not draw lots among seventeen “final” files.
