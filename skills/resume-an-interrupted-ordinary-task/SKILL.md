## 中文

当一项普通非紧急任务因电话、出门、休息或其他事被中断，你回来时有一张恢复便签或部分成果，却不确定**什么真的做完、什么仍待办、外界有没有变**时加载。目标是从实际证据重新取得一个安全的下一动作，并真正做出一点可观察进展。这不是中断前写便签，也不诊断注意力或靠“重新振作”替代核对。

### 准备与输入

找回中断前最近的任务记录、实际文件/物品/工单，以及此刻能看到的状态；记便签何时写的。若便签不存在，先从实际成果与原任务要求辨认最后可验证的部分，不凭记忆重复一个可能已经发送、付款或交接的动作。服务时段、他人回复或物件位置可能在中断期间变化，先看当前信息。

### 执行

1. **把旧记录当线索而非新事实。** 读“完成了什么、卡在何处、当时计划的下一步”，和当前文件、物件或服务状态逐一对上。写三列：“确实完成并有证据”“已开始但结果未知”“尚未开始”。不要把便签的“准备发”误读为“已经发”。
2. **先核可能重复造成后果的动作。** 若下一步涉及再发消息、重新购买、再次预约、移动别人共用物或其他不可轻易撤销动作，查实际发送记录、收据/预约状态或接手人答复；查不清时停下问相关正式方。普通恢复不等于盲按一次重复键。
3. **更新变了的依赖。** 比较截止、开放时段、对方消息、材料位置与可用设备；原路径失效就标“条件变了”，回到任务目标选可用下一步，而不是继续执行旧便签的命令。如果需要专业、财务、医疗或危险操作判断，交合格负责人。
4. **选一个现在能结束的小动作。** 例如打开确实的当前稿补完一段、把已核对信息发给正确接收人，或把需要他人决定的问题发出去。写明“开始需要__，完成看到__，若__就停”；动作应产生实际变化，而非又做一份漂亮的重启计划。
5. **做完更新恢复点。** 记录新状态、文件/物件所在、已经发生的对外动作、剩余未知和下一步；原便签标为历史版本，不维护两条互相矛盾的权威状态。任务尚未全部完成就诚实写“继续中”。

### 完成与停止

你已核对旧便签与当前证据，区分完成/未知/待做，避免重复不可逆动作，做出一项可见的下一进展或明确停在应向谁求证的点，本轮重新进入完成。**恢复成功不是整项任务完成。** 证据冲突、共享资源已被他人改动、专业风险或缺关键权限时先停，不用“试试看”覆盖现状。

### 常见报错与补救

- **便签写“下一步发送”，但发件箱已有：** 核收件人、时间和内容，别把同一件事再发一遍。
- **多个文件都叫“最新”：** 查实际修改时点与可验证内容，选唯一当前版本，保留旧版来源。
- **中断期间别人已回复：** 先读实际答复，再决定下一步，别照旧问题再问。
- **忘了便签放哪：** 从原任务要求、最近可靠的成果和实际外部记录恢复最小状态；未知就标未知。
- **重读很多资料但没有动手：** 选一个现在有输入且会留下结果的小动作，做完再决定是否继续。

### 假设、替代与副作用

适用于普通可退出任务，不处理事故抢救、付款授权、数据恢复命令、医疗或人事法律问题。中断的长度、工具和个人记忆差异很大，恢复用纸笔/可访问数字记录都行。视觉、行动、语言或注意力条件不同，可请可信授权者读回当前状态或缩小下一动作，不把需要更多核对时间当失败。副作用是几分钟前“显然该做”的一步可能已经失效，省下的重复代价更大。

## English

Load this Skill after an ordinary nonurgent task was interrupted by a call, travel, rest or something else. You have a recovery note or partial output but are unsure **what really finished, what remains and whether conditions changed**. Use current evidence to choose one safe next action and make some observable progress. This is not writing a note before the pause or diagnosing attention, and “getting motivated again” is no substitute for checking.

### Preparation and inputs

Find the latest saved note, actual file, object or case and what you can see now; note when the old note was written. If no note remains, identify the last verifiable output and original request rather than repeating an action that may already have sent, paid or handed something over. Hours, replies and item locations may have changed during the pause. Read current information first.

### Execution

1. **Treat the old note as a clue, not a fresh fact.** Compare “done, blocked and next” in it with current files, objects or provider states. Make three columns: definitely done with evidence, started but result unknown, and not begun. “Ready to send” in a note is not “sent.”
2. **Check before repeating a consequential action.** For another message, purchase, booking, movement of someone else's shared item or another hard-to-undo action, inspect actual sent messages, receipts, bookings or handoff replies. If the state is unclear, pause and ask the appropriate real source. Resuming is not pressing the same button blindly.
3. **Update dependencies that changed.** Check deadlines, opening hours, replies, material location and available tools. For an invalid old path, mark “conditions changed” and choose from the task's actual goal instead of executing an outdated note. Qualified owners handle professional, financial, medical or hazardous decisions.
4. **Choose one small action with a finish.** Complete a paragraph in the actual current draft, send checked information to the right recipient or ask the named owner for a required decision. Write “needs __ to start, finished when __ is visible, stop if __.” The action should change the real work, not merely create another impressive restart plan.
5. **Update the recovery point after acting.** Record new state, file or item location, actual external actions, remaining unknowns and next step. Mark the old note historical instead of keeping two contradictory authoritative states. If the whole task is not finished, say “in progress.”

### Success and stop

You reconciled the old note with current evidence, separated done, unknown and pending, avoided repeated hard-to-undo actions, and made one visible next move or paused at a named person or source for confirmation. **A successful restart is not completion of the entire task.** Stop for conflicting evidence, shared resources changed by others, specialist risk or missing authority rather than overwriting reality to “see what happens.”

### Common errors and recovery

- **The note says “send next,” but Sent already contains it:** Verify recipient, time and content before sending again.
- **Several files are all named “latest”:** Check actual modification and verifiable content, choose one current version and keep older provenance.
- **Someone answered during the interruption:** Read the actual reply before asking the old question again.
- **The note is missing:** Recover a minimal state from original requirements, reliable output and actual external record. Mark unknowns unknown.
- **You reread for a long time without acting:** Pick one input-ready action that leaves a result, then decide whether to continue.

### Assumptions, alternatives and side effects

This is for ordinary exit-able tasks, not emergency response, payment authorisation, system data-recovery commands, medical or employment-law matters. Pause length, tools and memory vary. Paper or accessible digital notes both work. For sight, mobility, language or attention needs, ask trusted authorised help to read current status or reduce the next action; extra checking time is not failure. A step that seemed obvious minutes ago may now be stale, which is cheaper to discover before repeating it.

### Sources

- Original synthesis. Compare an old recovery point with current evidence, separate done, unknown and undone, screen for duplicate consequences, and take one visible next action. This is not a promise the whole assignment is finished.
