## 中文

当你将用云端链接分享一份普通、低敏感文件，或想确认已分享文件的访问范围时，加载这份 Skill。目标是**在你有权限查看的实际共享界面里，对照预期对象和操作权限核对当前状态**，必要时由有权者调整并再次查看。复制到私聊的链接并不会自动只对那一个人开放。

只处理本人有权管理的普通文件。不要借用别人账号、索要密码、绕过组织策略，或拿身份证件、医疗/财务记录与机密项目练习。你看不到的组织成员、继承权限或管理员策略，应交给实际文件所有者或管理员，不靠猜。

### 准备与输入

先写清楚：哪一个文件、谁需要访问、只看/评论/编辑中的哪一种、是否有结束时间。打开文件真实所在的云盘或文档应用，确认文件名和内容版本；不要把一个同名副本的分享设置当成目标文件的设置。判断这是你可管理的个人文件，还是由团队/上级管理的共享文件夹内容。

### 执行

1. **打开真实的共享或“管理访问”界面。** 查看直接添加的人或群组、现有链接的受众、每种角色，以及文件是否在本来就共享的文件夹或站点里。界面若只显示部分结果，别据此宣称“只有这些人”。
2. **把预期与实际逐项对照。** 预期是两人查看，却显示“任何知道链接的人可编辑”，就是范围不符。预期是某位具体人员，却选择了“组织内任何持链接者”，也不是同一种限制。群组成员和父文件夹的访问可能比表面上的名单更广。
3. **只在有权范围内调整。** 若这是你管理的文件，按实际应用提供的选项选择与需求相符的具体人员或更窄受众，以及足够完成任务的角色。若已有广泛链接、直接授权或继承权限，单纯新建一个更窄的链接未必撤销旧访问；查清并按有权范围处理，影响他人的共享项目先问所有者。
4. **提交后重新查看。** 关闭设置再打开同一文件的共享界面，核对对象、角色、链接受众和是否仍有其他有效路径。若应用显示“更改待保存”“无法修改”或组织限制，标为未完成，不发送链接来试运气。
5. **用正确身份验证使用需求。** 需要确认别人能打开时，让预期接收者用自己的账号尝试并告诉你结果；不要让其交出登录信息，也不要借用其设备假扮身份。对方打不开时核对账户、邀请和权限；不要直接把范围放大到“所有持链接者”。
6. **记录当前边界。** 简短记下“文件/受众/角色/链接类型/未确认项”。若共享仅暂时需要，在你有权且实际平台支持时记录结束时复查或停止共享的时间；不要把提醒当成权限自动到期。

### 完成条件

你在实际提供方界面看到了目标文件的当前直接、链接及可见的继承访问，与预期用途相符；必要的修改已保存并重新核对。若群组成员、父文件夹或组织策略不可见，明确写出未知并交给有权者；只复制了链接或看见“已分享”不算完成。对方能否打开需要其本人反馈，不能靠你自己登录的视角证明。

### 常见报错与补救

- **“特定人员”链接建立后仍有旧公开链接：** 查看全部有效链接与直接访问；有权时处理旧路径，不能处理就停止声称仅限特定人员。
- **文件夹原本就共享给更多人：** 文件层的窄设置可能无法消除继承访问；问所有者是否需移到另一个有权位置或调整父级，不直接改共享项目结构。
- **对方请求访问：** 确认请求账号确实是预期对象，并给所需的最小角色；不因着急就改成“任何持链接者”。
- **你看不到管理访问选项：** 说明当前没有相应权限，交所有者处理；不要借账号或绕过限制。
- **更改后链接仍打不开：** 检查实际文件、邀请对象、保存状态和账号类型；不要把给更多人开放当作唯一修法。

### 假设、替代与现实副作用

云盘对“受限”“组织”“任何持链接者”、查看与编辑、继承和到期的实现各有差异，以实际界面和服务方说明为准。可用键盘或屏幕阅读器逐项检查受众和角色，不靠锁图标猜权限。缩小访问可能让先前协作者暂时打不开；先确认谁会受影响。权限界面是可见证据，不是你能列出所有实际阅读者的证明。

## English

Load this Skill when you will share an ordinary low-sensitivity file through a cloud link, or want to check who can access a file already shared. **Use the actual provider's sharing interface you are authorized to see to compare intended people and actions with current access**, and have an authorized person adjust and recheck it if needed. Pasting a link into a private chat does not automatically restrict the link to that one person.

Handle only an ordinary file you may manage. Do not borrow another person's account, request a password, bypass organization policy, or practice with identity, medical, financial, or confidential files. If group membership, inherited access, or admin policy is invisible to you, take that unknown to the actual owner or administrator rather than guessing.

### Preparation and inputs

State which file, who needs access, whether they need viewing/commenting/editing, and any end time. Open the real cloud drive or document app and check the filename and version; a same-named copy may have different sharing settings. Determine whether this is your own managed file or one inside a shared project folder controlled by someone else.

### Execution

1. **Open the real Share or Manage access view.** Inspect directly added people or groups, the audience for existing links, each role, and whether the file lives in a shared folder or site. If the interface shows only part of the picture, do not claim “only these people” have access.
2. **Compare intended and actual access.** If two people should view but the file says “anyone with the link can edit,” the scopes differ. “Anyone in the organization with the link” also differs from one named person. Group membership and parent-folder access may be broader than the visible direct list.
3. **Change only what you control.** If you manage the file, use the app's available settings for the intended specific people or narrower audience and the role needed for the task. A new narrow link may not revoke an older broad link, direct grant, or inherited access. Check those routes and handle them only with authority; ask the owner before changing a shared project's access.
4. **Reopen after saving.** Close and reopen sharing for that exact file. Check people, roles, link audience, and other visible access paths again. If a change is pending, refused, or blocked by organization policy, mark it unfinished; do not send a link hoping it worked.
5. **Verify the recipient's need using their own identity.** If their ability to open matters, ask the intended recipient to try with their own account and tell you what happened. Do not request credentials or impersonate them on their device. If access fails, check the account, invitation, and permissions rather than immediately broadening to “anyone with the link.”
6. **Record the current boundary.** Note file, audience, role, link type, and unknowns. If access is temporary, record a time to review or stop sharing if you have authority and the platform supports it. A reminder is not an automatic permission expiry.

### Success

The actual provider interface shows that the target file's direct, link, and visible inherited access fit the intended use. Any needed changes were saved and rechecked. If group members, parent-folder access, or organization rules are not visible, name the unknown and hand it to someone authorized. A copied link or “shared” badge is not enough. The intended recipient's ability to open needs their own feedback; your signed-in view cannot prove it.

### Common errors and recovery

- **A “specific people” link coexists with an old public link:** Inspect all effective links and direct access. Handle the old route if authorized; otherwise stop claiming access is limited to the named people.
- **The parent folder is shared more broadly:** A narrow file setting may not remove inherited access. Ask the owner whether the file needs a different authorized location or parent change; do not restructure a shared project unilaterally.
- **Someone requests access:** Check that the requesting account is the intended person and grant only the needed role. Do not switch to “anyone with the link” in a hurry.
- **Manage access is unavailable to you:** State that you lack the permission and ask the owner. Do not borrow an account or work around the restriction.
- **The link still fails after a change:** Check the exact file, invitee, saved state, and account type. Wider public access is not the only fix.

### Assumptions, alternatives, and known side effects

Cloud providers differ in restricted, organization, anyone-link, view/edit, inheritance, and expiry behavior. Follow the actual interface and provider guidance. A keyboard or screen reader can inspect audience and role labels; do not infer access from a lock icon. Narrowing access may temporarily block a prior collaborator, so identify who is affected first. The permission UI is visible evidence, not proof that you can list every person who has read the file.
