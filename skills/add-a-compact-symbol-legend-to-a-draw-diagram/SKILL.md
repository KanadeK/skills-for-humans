## 中文

你的一张 Draw 图同时用普通动作框、判断菱形和不同线义，读者可能猜错符号意思时使用本篇。成果是一份短图例，图例样式与图内真实对象一致，未使用的符号不凑数。它解释视觉编码，不重新定义流程规则。

### 准备与输入

保存 ODG 副本，清点图中真实用到的形状、颜色和线型，最多挑需要解释的几项。若全图只有一种动作框和一条简单箭头，图例可能多余，可停止。找页边不遮主流程的留白，定一行短义，不复制长段说明。

### 执行

1. 在空白处建小标题“图例/Legend”和少量符号样本，形状/线型与原图一致。
2. 每样本写一条确切含义，如普通步骤、判断或附着流程线，不混用相反术语。
3. 逐项回原图找对应符号，核没有图例有而图里没有的项目，也没有关键符号漏解释。
4. 普通尺寸下读图例与主图，核不遮挡节点/边界，保存重开。

### 完成、常见问题与恢复

图例短而准确、符号对应真实图对象，主流程空间未被挤坏。

- **图例样本与原图不同：** 从现有样式复制或统一改正。
- **解释过多：** 删未使用或显而易见项目。
- **主图被遮：** 移到边角或另页。

### 假设与边界

图例不能替代真实流程语义核对。你负责符号含义；正式行业标准图例不在此范围。

## English

Use this Skill when a Draw diagram uses action boxes, decision diamonds and different line meanings that a reader may guess incorrectly. Finish with a short legend whose samples match actual diagram objects and no unused symbols added for decoration. The legend explains visual code; it does not redefine process rules.

### Preparation and inputs

Save ODG copy and inventory shapes, colors and line styles actually used, selecting only meanings needing explanation. If the diagram has one action box and one simple arrow, a legend may add no value. Choose whitespace outside main flow and short definitions.

### Execution

1. Create a small Legend heading and a few samples matching actual shapes/lines.
2. Give each sample one precise meaning such as action, decision or connector, without contradictory terms.
3. Find each sample in source drawing, removing unused entries and adding only important missing meaning.
4. Check legend and flow at normal size for overlap, then save/reopen.

### Success, common problems, and recovery

Legend is brief and accurate, maps to actual objects and does not crowd main flow.

- **Legend sample differs:** Copy actual style or correct both.
- **Too many entries:** Remove unused/obvious items.
- **Flow covered:** Move to margin or detail page.

### Assumptions and limits

A legend cannot replace process-rule verification. You own symbol meanings; formal industry notation is outside scope.
