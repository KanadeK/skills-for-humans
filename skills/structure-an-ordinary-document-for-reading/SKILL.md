## 中文

当你自己写的一份普通数字文档看起来有标题、步骤和链接，但读者只能从头到尾翻或靠猜字体大小理解层级时，加载这份 Skill。目标是让**标题、列表和链接的实际结构与内容顺序一致**，使读者能按段落导航。给有信息的图片补说明是另一个独立动作；把文档导出成 PDF 也不会自动修复源文档的结构。

只编辑你有权改动的低敏感内容。正式无障碍认证、专业表单、法律/医疗/财务材料和跨平台兼容性承诺不在这里；这个流程是普通创作补丁，不是符合某项标准的证明。

### 准备与输入

在原编辑器打开文档，确认当前版本并保存一份你能找回的工作状态。用一句话写出读者要找的主要内容，再快速浏览各段：哪些是真章节标题，哪些只是强调文字，哪些是实际步骤或清单，哪些链接只写了“点这里”。

### 执行

1. **先排内容顺序。** 把标题、说明、步骤和结论放成能从头到尾理解的顺序；若靠左右栏、空格或表格才看得懂先后关系，先用普通段落和真实列表表达。视觉排版可以后做，不能承担唯一逻辑。
2. **给标题用编辑器的真正标题样式。** 文档标题之后，主要部分用同级标题，子部分降一级。不要为了好看直接把普通字加粗放大，也不要从一级一下跳到四级。标题要说明该段内容，例如“如何提交修改”，而不是“其他”。
3. **把步骤与并列项设为真实列表。** 顺序重要的步骤用有序列表，普通并列项用无序列表；不要手敲空格和数字伪装。段落内的解释留在对应条目内，避免视觉上靠近却在朗读顺序中被拆散。
4. **让链接自己说得清。** 把“点击这里”改成目的地或动作，如“查看活动地点和开放时间”。如果同一词指向不同地方，把区别写出来；不要只用颜色暗示它可点。更改文字时核对链接仍指向正确位置。
5. **用大纲与线性阅读检查。** 打开编辑器的大纲/导航栏，看标题是否按内容顺序出现、层级是否能解释文档。再按自然顺序读一遍，必要时用朗读或屏幕阅读器模式；若有编辑器可及性检查器，处理它指出的相关问题，但通过检查不等于真人能顺利使用。
6. **保存并重新打开。** 核对标题、列表、链接和内容仍在；如之后要导出或发送，再对那个导出副本单独检查。若文档中图片承担额外信息，另给它文字替代，不靠本 Skill 的标题步骤覆盖。

### 完成条件

读者能从文档大纲找到主要部分，按标题/列表顺序读懂正文，链接文字离开上下文仍有意义。源文档重新打开后结构仍在。若编辑器不支持真实标题或列表，明确记录限制，并用可用的文本顺序降低障碍；不能声称达到正式无障碍合规。

### 常见报错与补救

- **标题看起来对，大纲却为空：** 这是视觉加粗而非真正标题；用编辑器的标题样式替换，重看大纲。
- **大纲里每一行都成了标题：** 把普通强调文字恢复为正文，仅保留表达章节的标题。
- **列表朗读顺序错了：** 检查是否用了文本框、表格或手敲编号，改为真实列表和连续段落。
- **链接都叫“这里”：** 逐个改成具体对象或动作，并确认目标没变。
- **检查器显示通过，但读起来仍跳跃：** 人工按阅读顺序走一遍，必要时请真正使用该阅读方式的人反馈；自动检查没有替你完成体验验收。

### 假设、替代与现实副作用

不同编辑器对标题级别、列表和导航的菜单不同，但“真实结构比只改外观更容易导航”的目标一致。读者的视觉、听觉、注意力和设备条件各不相同；可用键盘、朗读或普通大纲做初步核对。修改样式可能改变版面，之后导出仍须重查。一个有用的大纲可能让文档比以前显得更诚实。

## English

Load this Skill when an ordinary document you wrote *looks* as if it has headings, steps, and links, but a reader must scroll from the start or guess structure from font size. Make the **real heading, list, and link structure match the reading order**, so someone can navigate by section. Describing an informative image is a separate action. Exporting to PDF does not automatically repair the source structure.

Edit only ordinary low-sensitivity content you are allowed to change. Formal accessibility certification, specialist forms, legal, medical, or financial materials, and cross-platform guarantees are outside this Skill. This is an ordinary authoring repair, not proof of conformance with a standard.

### Preparation and inputs

Open the current version in its source editor and save a working state you can find again. State the main things a reader should locate. Scan the paragraphs: which are real section headings, which are merely emphasized words, which are actual steps or lists, and which links say only “click here”?

### Execution

1. **Order the content first.** Put title, explanation, steps, and conclusion in an order that makes sense when read from start to finish. If columns, spaces, or a table are the only way to understand sequence, express it in ordinary paragraphs and real lists first. Visual layout may follow, but should not be the only logic.
2. **Use real heading styles.** After the document title, give peer sections the same level and subsections the next level. Do not only enlarge or bold ordinary text for appearance, or jump straight from level one to level four. A heading should name the section's work, such as “Submit a revision,” rather than “Other.”
3. **Use real lists for steps and peers.** Choose an ordered list when sequence matters and an unordered list for peers. Do not hand-type spaces and numbers to imitate one. Keep an explanation with its related item so it is not visually close but separated in the reading order.
4. **Make link text meaningful.** Replace “click here” with the destination or action, such as “See the venue and opening hours.” Distinguish links with different targets. Do not rely on color alone to say something is clickable. Check that the target remains correct after editing the words.
5. **Check the outline and linear reading.** Open the editor's outline or navigation pane. See whether headings appear in content order and their levels explain the document. Read through in natural order, using read-aloud or a screen reader view if useful. Address relevant findings from an available accessibility checker, but a green check is not a real-reader acceptance test.
6. **Save and reopen.** Check headings, lists, links, and contents survived. If you later export or send, inspect that output separately. If an image carries additional information, give it a text alternative separately; heading work does not cover it.

### Success

A reader can find major sections from the outline, understand text in heading/list order, and know a link's purpose without its surrounding sentence. The reopened source still has the structure. If the editor lacks real headings or lists, record the limit and improve what you can through text order; do not claim formal accessibility compliance.

### Common errors and recovery

- **Headings look right but the outline is empty:** Bold text is visual emphasis, not a real heading. Apply the editor's heading styles and check the outline again.
- **Every line appears in the outline:** Return ordinary emphasis to body style; reserve headings for real sections.
- **List reading order is wrong:** Check for text boxes, layout tables, or manually typed numbers. Use a real list and continuous paragraphs.
- **Every link says “here”:** Rename each by destination or action and verify its target.
- **The checker passes but reading still jumps:** Walk the real reading order and, when possible, ask someone who uses that route for feedback. Automation did not test the lived reading experience.

### Assumptions, alternatives, and known side effects

Editors vary in menus for heading levels, lists, and navigation, but real structure is more navigable than appearance alone. Readers differ in vision, hearing, attention, and devices. A keyboard, read-aloud mode, or outline can support an initial check. Style changes may shift layout; exported copies still need checking. A useful outline may reveal more truth about the document than its old typography did.
