## 中文

当下载目录或桌面堆了一批普通文件，导致你看不出哪些要留、哪些还要处理、哪些能删除时，加载这份 Skill。目标是**在一小批文件中做出可解释的分类和必要动作**，而不是一口气清空目录。单份文件的命名归档、照片挑选、备份验证和敏感资料销毁各有不同任务。

只处理你有权管理的低敏感个人文件。跳过系统或软件目录、别人的共享文件、带凭据或私密记录的内容；不要为“看一下”而运行来历不明的下载程序。删除到废纸篓/回收站的行为在不同设备、网络位置和云服务下可能不同，不能默认随时可恢复。

### 准备与输入

打开下载目录或桌面，选一个看得完的小范围，例如屏幕上最近的十来个文件，记下本次范围。准备三个临时判断：“留并归位”“仍有动作要做”“确认可丢弃”。这些是判断标签，不要求你创建三个新的永久文件夹。先看文件名、位置、类型和实际内容；扩展名与图标不能独自证明文件有用或无用。

### 执行

1. **逐个回答用途。** 这是什么？是否还要打开、填写、回复或交付？是否已经有经核对可打开的所需版本？不了解的文件先标待确认；不要把“名字像副本”当成可以删除的证据。
2. **把要留的文件归位。** 选用途对应的现有文件夹；需要时给单份文件一个能找回的名称。移动前看是否有同名文件、应用引用或共享链接，遇到冲突不覆盖，先保留原位。归位后从目标位置打开一次正确内容。
3. **给未完成事项一个下一步。** 如果文件还需要签回、阅读、编辑或问别人，就保留在能找到的位置，并写下一项具体动作及合适时间。别为了桌面整洁把未完成的事藏进名为“待整理”的深层文件夹。
4. **对删除候选做最后确认。** 确认是**这个具体文件**、你有权删除、内容已查看、没有仍需使用的版本或关联任务；若它来自同步盘或共享位置，还要查删除会影响谁。对不能确认的文件保持原样。不要用全选、按扩展名批量删，或把整目录扔进废纸篓。
5. **只把确认的候选移入实际平台的废纸篓或回收站。** 在界面确认目标文件名与数量，执行普通删除；若提示将直接永久删除、影响共享成员或跳过可恢复位置，取消并重新判断。此轮不清空废纸篓/回收站，不承诺它在任何平台保留固定天数。
6. **回看本批结果。** 确认归位文件能打开、待办仍能定位、被删除的恰好是预定候选；误删时立即检查当前平台可用的恢复入口，按其实际状态恢复。若找不到恢复入口，停止继续删除，不把未验证的恢复方法当保证。

### 完成条件

本批每个文件都有明确去向：可找回的保留位置、可执行的下一步，或经逐项确认后的普通删除；没有未知文件被强行归类。你能指出尚未处理的文件在哪里。桌面是否一片空白不是完成条件。

### 常见报错与补救

- **两个文件看起来重复：** 分别打开并比较实际内容与版本；不能确认哪份仍需要时，两份都暂留，不以文件大小或日期单独裁决。
- **下载的是安装程序或压缩包：** 不因扩展名而运行它；若来源和用途不明，保持待确认。安装软件、检查来源和卸载都不在本 Skill 的动作里。
- **共享或云端文件出现删除提示：** 先确认所有权和其他人的访问影响；不清楚就取消。你本地看到的“移到废纸篓”不一定只影响你。
- **移动时提示同名：** 取消覆盖，核对目标与来源内容后决定保留两份、改名或停下。
- **误删了文件：** 停止本批继续删除，立即到实际平台的废纸篓/回收站查找并尝试恢复；若不存在，寻求该平台的正式恢复路径，别声称一定能找回。

### 假设、替代与现实副作用

本 Skill 适合本人可管理的普通本地或已了解规则的云端文件。不同平台的删除、同步、保留时间和共享权限不同；以眼前界面和提供方规则为准。可使用列表视图、键盘、搜索或屏幕阅读器逐项核对，视觉缩略图不是唯一方式。清理后可能发现一份迟迟没处理的表格；它是待办，不是文件管理失败。

## English

Load this Skill when an ordinary batch of files in Downloads or on the Desktop makes it hard to tell what to keep, act on, or delete. Make an **explainable decision for a small batch and take the necessary action**. Emptying the whole folder is not the goal. Naming one file, curating photos, proving a backup, and destroying sensitive records are separate tasks.

Handle only low-sensitivity personal files you are allowed to manage. Skip system or application directories, someone else's shared files, credentials, and private records. Do not run an unfamiliar download just to see what it is. Moving something to Trash or Recycle Bin works differently across devices, network locations, and cloud services; recovery is not guaranteed.

### Preparation and inputs

Open Downloads or Desktop and choose a small scope you can inspect, such as roughly a screenful of recent files. Note the scope for this pass. Use three temporary judgments: “keep and file,” “action still needed,” and “confirmed discard.” These are decisions, not a requirement to make three permanent folders. Inspect each name, location, type, and actual contents. An extension or icon alone cannot prove a file useful or useless.

### Execution

1. **Ask what each file is for.** What is it? Must it still be opened, filled, answered, edited, or delivered? Is there another needed version that you have actually opened? Mark an unknown file pending. A name that looks like “copy” is not deletion evidence.
2. **File what you need to keep.** Choose an existing folder by purpose and give an individual file a findable name if needed. Before moving, check for a matching name, application reference, or shared link. Do not overwrite a collision; keep the original in place while uncertain. Open the right contents once from the destination.
3. **Give unfinished files a next action.** If a file still needs a reply, reading, edit, or another person's answer, leave it somewhere findable and record one specific next action and suitable time. Do not hide unfinished work deep in a folder called “to sort” merely to clear the desktop.
4. **Confirm each discard candidate.** Check that this is **the exact file**, you may delete it, you inspected its contents, and no needed version or task depends on it. If it is in a synced or shared place, check who else a deletion affects. Leave uncertain files untouched. Do not select all, delete by extension, or throw away the entire folder.
5. **Move only confirmed candidates to the actual platform's Trash or Recycle Bin.** Check the target names and count in the interface, then use ordinary delete. If it says the action is immediately permanent, affects collaborators, or bypasses a recoverable location, cancel and reconsider. Do not empty Trash or Recycle Bin in this pass or promise a fixed retention period on every platform.
6. **Review this batch.** Open a filed item, locate the pending actions, and check that the deleted items were exactly the intended candidates. If you deleted the wrong file, promptly check the current platform's recovery entry and restore it if actually available. If no recovery entry appears, stop deleting; an unverified recovery method is not a promise.

### Success

Each file in this batch has a clear outcome: a retrievable kept location, an actionable next step, or individually confirmed ordinary deletion. Unknown files were not forced into a category. You can point to where pending files are. A completely empty desktop is not a completion requirement.

### Common errors and recovery

- **Two files look duplicated:** Open both and compare actual content and version. If you cannot tell which remains necessary, retain both for now; size or date alone is not enough.
- **A download is an installer or archive:** Do not run it because of its extension. Keep an unclear source or purpose pending. Installing, verifying software origins, and uninstalling are outside this Skill.
- **A shared or cloud file shows a deletion warning:** Check ownership and others' access first; cancel if uncertain. “Move to trash” on your screen may affect more than you.
- **Moving prompts for replacement:** Cancel the overwrite, compare source and target contents, then decide whether to keep both, rename, or stop.
- **You deleted the wrong file:** Stop this batch's deletions. Check the actual platform's Trash or Recycle Bin and try to restore it. If it is absent, use that platform's official recovery path; do not claim it can certainly be found.

### Assumptions, alternatives, and known side effects

This covers ordinary files you manage locally or in a cloud location whose rules you understand. Deletion, syncing, retention, and sharing permissions differ by platform; follow the visible interface and provider rules. A list view, keyboard, search, or screen reader can support item-by-item checking; visual thumbnails are not required. Clearing clutter may reveal a long-neglected form. That is a to-do item, not a filing failure.
