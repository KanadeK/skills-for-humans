## 中文

当你手里有同一普通材料的几份副本，如“最终”“最终2”“最新改”，却不能确定下一步该从哪份继续时，加载这份 Skill。目标是有依据地指定**一份当前工作稿**，把未决差异留待核对。这里没有已知误覆盖要回退；若确实覆盖了有用内容，用本域误覆盖恢复 Skill。

### 准备与输入

把候选限制在同一份任务的少量文件，记录各自所在位置、文件名、修改时间、你知道的来源和这次用途。只处理你有权查看的低敏感普通内容。若文件由多人维护，先确认谁有权决定当前稿；不是由你决定的，不靠自己给文件改名宣布权威。

### 执行

1. **保留候选原状。** 暂时不覆盖、删除、移动或同步合并任何一份。给每份写一个临时编号和位置，避免一边比较一边把证据改掉；若应用只有一个云端共享文件，先看它的历史而非在多人同时编辑时另造“权威副本”。
2. **定义选稿标准。** 写清此刻要继续什么：例如用于下一次讨论的要点、仍需补完的表格，或已经获确认的内容。确认负责人、截止点和必须保留的段落；“修改时间最新”“文件最大”都不能独自充当正确性标准。
3. **比实际内容与来源。** 逐份打开候选，核相同区域的标题、关键段落/数值、评论、缺页和是否可读。按位置或版本历史判断哪份包含哪些修改；仅复制文件可能改变时间戳，不能据此推断内容更新。把互相矛盾的地方列成短表：位置、A 怎么写、B 怎么写、谁能确认。
4. **确定可用部分与未决部分。** 如果一份明显满足已确认要求，先以它作为候选工作底稿；其他独有而可核的改动，按自己的权限加到**新副本**并标来源。若两份有冲突或多人同时改，问有决定权的人确认，不做“较新的大概对”。
5. **命名并交接唯一当前稿。** 在有权使用的位置保存一份新的工作稿，写上用途/日期和负责人认可的状态；重开核关键内容，并向实际协作者说明“从这份继续、还有哪些未决”。保留旧候选作对照直到确认，不把旧件批量删除。若始终无法判断，留下候选清单与待核问题，明确暂停继续编辑。

### 完成、常见问题与补救

你有一份重开可读、来源和用途清楚的当前工作稿，并把冲突标待核或获负责人确认；或有一份可供负责人裁决的候选差异清单。仅把文件名改成“真正最终版”，不算解决版本混淆。

- **两个版本都各缺一段：** 逐项抽出可核内容到新副本，冲突留标记；不把整个 A 覆盖 B。
- **最新时间来自复制或下载：** 核正文、评论或应用历史，而非排序结果。
- **你没有决定权：** 不代替负责人宣布哪份有效；交候选和差异，请其指定。
- **大家还在同时编辑：** 在共享应用里确认真实当前文档及协作状态；先协调停止重复分支再合并。
- **读屏或文件格式限制比较：** 用可访问文本视图、朗读或可信协助逐段核关键处；无法核内容时保留候选并停。

### 假设、替代与现实副作用

本篇只处理少量普通候选文件，不替组织制定版本控制政策。应用的比较功能和历史权限不同；纸面差异表也可用。多留几份暂时占空间，但在决定前删掉含独有改动的文件风险更大。若候选本身含敏感或受管信息，遵守其实际存放与分享规则。

## English

Load this Skill when you have several copies of one ordinary item named “final,” “final2,” or “latest edits” and cannot tell which one to continue from. Identify **one current working copy** on evidence and keep unresolved differences available for review. This starts without a known accidental overwrite; use the separate overwrite-recovery Skill when useful content was actually replaced.

### Preparation and inputs

Limit candidates to a few files for one task. Note location, filename, modification time, known origin, and intended use for each. Handle only ordinary low-sensitivity material you may view. If several people maintain it, confirm who may decide the working copy. Renaming a file yourself does not grant you authority over others' work.

### Execution

1. **Keep candidates unchanged.** Do not overwrite, delete, move, or sync-merge them yet. Give each a temporary ID and location so comparison does not alter the evidence. If there is one cloud-shared file, inspect its history rather than inventing a second authoritative copy while others edit.
2. **Set selection criteria.** Name the next real use: discussion notes, a table to finish, or content already approved. Identify owner, time boundary, and required passages. Newest timestamp and largest file size alone do not establish correctness.
3. **Compare content and provenance.** Open each candidate and check matching sections for titles, key text or figures, comments, missing pages, and readability. Use location or app history to understand which changes each contains. Copying a file can change its timestamp without making content newer. List contradictions briefly: location, A's text, B's text, and who can decide.
4. **Separate usable and unresolved parts.** If one version meets confirmed requirements, use it as the candidate base. Move other unique, verifiable changes into a **new copy** within your authority and note their sources. Ask the decision owner about conflicts or concurrent edits; “the newer one probably wins” is not a decision rule.
5. **Name and hand off one current copy.** Save a new working copy in an authorised place, with purpose, date, and owner-approved status. Reopen key content and tell actual collaborators which file to continue and what remains unresolved. Retain old candidates until checked instead of bulk deleting. If you still cannot decide, leave a candidate list and questions and explicitly pause editing.

### Success, common problems, and recovery

You have a readable reopened working copy with clear purpose and provenance, and conflicts are confirmed by the owner or marked for checking. Alternatively, you have a candidate-difference list ready for their decision. Renaming a file “real final” alone does not resolve a version conflict.

- **Each version has a different useful passage:** Extract verified content into a new copy and mark conflicts; do not overwrite all of B with A.
- **The newest time came from a copy or download:** Check text, comments, or app history rather than the sort order.
- **You lack decision authority:** Do not declare one version valid for the group. Hand over candidates and differences for the owner to choose.
- **People are still editing:** Confirm the actual shared document and collaboration state, then coordinate stopping duplicate branches before merging.
- **A screen reader or format makes comparison hard:** Use accessible text, spoken reading, or trusted help for key sections. Retain candidates and stop when content cannot be checked.

### Assumptions, alternatives, and side effects

This handles a few ordinary candidate files, not an organisation's version-control policy. Comparison features and history access vary by app; a paper difference list also works. Keeping copies temporarily uses space but prevents deleting unique edits before a decision. Follow actual storage and sharing rules if any candidate is managed or sensitive.
