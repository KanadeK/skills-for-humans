# Skills for Humans：并行扩充批次

状态：总控排程。基线是 v0.1.0 的 15 个 Skill；下面的 150 个题目是待审工作项，不是必须发布 150 个文件。每项最后都应有 `create`、`merge/update` 或 `not_promoted` 结论。用户目标、关键决策、输入输出和失败恢复相同的题目，只保留一个 Skill。

## 分工协议

1. 总控分配批次 ID，最多同时开启三个写作对话。每个对话只负责一个批次；没有领到的批次不抢做。第一组建议 B01、B13、B19，分别覆盖家务、社交和第一次尝试。
2. 每个对话从最新 `main` 建立独立 Git worktree 和 `codex/human-bXX-<scope>` 分支。先确认目标路径不存在；不要共享同一检出目录，不改外层 `D:\我的\GitHub` 的 Git index，不使用 `git add .` 或 `git add -A`。
3. 开始写作前读本文件、`AGENTS.md`、`docs/human-skill-format.md`、`SKILLS.md`、相关已有 Skill，以及 GitHub 上已开放的本项目 PR。对五个题目逐一比较用户目标与能力边界。若与现有或其他批次重叠，记录 `merge/update` 或 `not_promoted`，不要换标题硬造。题目与实际需要冲突时，在本批范围内替换，并在 PR 解释。
4. 每个新 Skill 保持中文原创、完整自然英文、`Runtime: Human`、直接对人说话、少量贴合场景的冷幽默、现实可观察的成功与恢复。默认 `Human test: Not yet / 尚未`；只有真实的人按步骤走过并记录证据才能改为已实测。必要的客观事实使用可信来源，引用只保留短链接与所支持的事实。
5. 每个批次提交自己的 `skills/<slug>/SKILL.md`、`SKILLS.md` 行和 `CHANGELOG.md` 的 Unreleased 项。不要改 README 中的 v0.1.0 历史数字，也不要改验证器、模板、其他批次的 Skill 或 Harvester。若确实发现格式缺口，先向总控报告。
6. 本地运行 `python scripts/validate_skills.py`、`python -m unittest discover -s tests`，并对新增 Skill 运行官方 `quick_validate.py`。抽查中英内容、来源、链接、可执行性和安全；自动测试不是人类实测。
7. 精确暂存并推送分支，开一个以 `main` 为 base 的 PR：标题 `feat(human): BXX <scope>`。PR 正文列出五项题目的裁决、每个新 Skill 的非重复理由、来源、验证结果及未实测限制。工作对话不得合并、打 tag 或发布 Release。
8. 总控按顺序验收并合并。前一个 PR 合并后，其余分支先同步最新 `main`，解决 `SKILLS.md` / `CHANGELOG.md` 冲突并重跑验证。一个批次在 main 的 CI 通过，才算完成。总控决定何时整批发布新版本。

给新对话的短指令：

> 在 `D:\我的\GitHub\skills-for-humans` 执行 `tasks/expansion-program.md` 的 BXX。先读分工协议和该批五个题目，从最新 main 建独立 worktree；完成真实去重、Human Skill 写作、验证、推送并开 PR。只交付 BXX，不合并或发布。把 PR 链接与五项裁决交回总控。

## 已有能力的排除基线

- 买菜计划、挑易腐食材、买后收纳；衣物分桶、洗衣机设置、羊毛洗护；现有食材备餐、食材功能替代、熟度与剩菜。
- 独自去陌生餐馆、尝试新爱好前先少买装备；给客服打电话、退错买商品；救过咸的菜、出门前发现将迟到。
- 本计划里的题目若只是上述能力的设备、地点或食材变体，优先更新原 Skill。每个批次仅拥有下表指定的“主问题”；相关问题可交叉链接，不得复制步骤。

## 跨批次边界与验收

- B01 负责厨房清洁；B25 负责仍在烹饪中的食物补救。B02 负责日常维护；B26 负责已经发生的衣物事故。B08/B09/B10 依交通方式分界；B12 只负责步行定位。B13/B14/B16/B17 是正常互动；B18/B30 是已发生错误或计划变更。
- 题目中出现真实价格、票务、航空、住宿、退换政策、家电按钮、洗护标签或地方回收规则时，引用当地/当期官方信息，并把需要用户现场确认的事实写明。医疗、法律、财务、危机干预、燃气/电气维修和危险化学操作继续排除。
- 质量先于数量。五个题目全被合并或拒绝也是有效批次，只要理由具体、没有遗留 pending；不能为了交差换名发布。
- 总控验收每个 PR 的去重判断、中文与英文实际可执行性、来源、安全和冷幽默分寸；必要时挑两份作为“没有 AI 的读者”从头走读。当前 15 个 Skill 均未有人类实测，后续不要用 CI 或 AI 审阅填补这个字段。
- 前三批 B01/B13/B19 验证协作节奏。它们在不同领域，适合并行。之后每次最多发三个、顺序合并，再按真实产量和重复率调整批次大小。新版本发布由总控另行安排，不由内容对话自行决定。
